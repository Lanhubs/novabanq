# NovaBanq Flutter app

This app connects to the [NovaBanq API](https://novabanq-api.onrender.com/docs). The [backend integration guide](https://github.com/Lanhubs/novabanq/blob/main/README.md) is the source for request bodies, response envelopes, and business error codes.

## Configure Firebase

The Firebase project identifiers and platform OAuth setup are external to this repository. Obtain them from the NovaBanq Firebase project owner. Configure the Android and iOS app registrations with FlutterFire, enable Email/Password, Google, and Phone sign-in, register Android SHA-1/SHA-256 fingerprints, and configure APNs for iOS phone auth. Google sign-in on iOS also needs the platform URL scheme and client ID generated by FlutterFire.

Run with build-time configuration (or equivalent `--dart-define-from-file`):

```sh
flutter run \
  --dart-define=FIREBASE_API_KEY=... \
  --dart-define=FIREBASE_APP_ID=... \
  --dart-define=FIREBASE_PROJECT_ID=... \
  --dart-define=FIREBASE_SENDER_ID=... \
  --dart-define=GOOGLE_CLIENT_ID=... \
  --dart-define=GOOGLE_IOS_CLIENT_ID=...
```

`GOOGLE_CLIENT_ID` is the Google web OAuth client ID used as the server client ID. `GOOGLE_IOS_CLIENT_ID` is the iOS OAuth client ID. The Firebase identifiers above are required. Without them, the app displays a setup error when authentication is attempted. The default API base URL is `https://novabanq-api.onrender.com/api/v1`; override it with `--dart-define=API_URL=...` for a local backend.

## Connected behavior

- Email registration uses Firebase Auth, requests an email OTP with `{}`, verifies a six digit code, creates the profile with all three legal names, country, and E.164 phone, offers tag claiming, then creates a five digit transaction PIN. The OTP resend delay comes from the API.
- Google sign-in uses Firebase Auth and asks the user to enter legal names before profile creation. It skips email OTP.
- The dashboard fetches the authenticated profile, including its actual reserved account number and full country suffix tag. It does not fabricate a wallet balance.
- Tag entry sends the base name only, validates its format, checks availability after 400 ms of inactivity, previews the server returned full tag, and claims it. A successful check is not treated as a reservation; claim errors are handled separately.
- Phone verification is a dashboard action. Firebase sends and validates the SMS, the credential is linked to the current user, the ID token is refreshed, and the backend is called with the E.164 phone. It is not required to browse the app.
- Identity verification is a dashboard action. The app captures a selfie, obtains a signed payload, uploads directly to Cloudinary with the signed folder and access mode, then submits the BVN and Cloudinary public ID. The backend's `status` decides the result.
- Protected API requests fetch a Firebase ID token immediately before sending and parse the shared `{success,data,error}` envelope. Business logic uses `error.code` where applicable.

The API client exposes profile lookup, name update, tag check/claim, phone verification, PIN set/verify/reset, email OTP send/verify, and identity upload/verify. A PIN reset needs a freshly verified Firebase phone claim before `resetPin`, followed by `setPin`.

The backend does not yet provide balance, recipient lookup, exchange rate, transfer, or transaction history endpoints. The app reports those actions as pending and never shows a successful transfer without a backend transaction. The ten digit account number is a NovaBanq internal placeholder, not a bank account. BVN and face decisions are currently mocked by the backend.

## Verification

```sh
flutter pub get
dart analyze lib
flutter test
```

End to end authentication requires a configured Firebase project, the backend's external services, and a device or Firebase test phone number. Do not add a backend SMS bypass. The backend's own integration tests require its `.env`, service account, and `FIREBASE_WEB_API_KEY`.
